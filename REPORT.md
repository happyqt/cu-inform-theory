# Отчёт

## Принятые решения

1. Я решил расширить формат конечным состоянием: `initial`, `transitions` и `by_state` в переключателе. Состояние хранит последние три символа либо выбранный навсегда режим. Отдельные несовместимые форматы не нужны; исходный JSON работает без изменений. Примеры и семантика приведены в FORMAT.md. Проверка стационарности сравнивает вероятности слов до и после сдвига; проверка независимости — с произведением маргинальных вероятностей. Конечный линейный базис позволяет выполнить обе проверки точно, включая недостижимые состояния и одинаковые скрытые модели.

2. Вероятности читаются из строк в `Fraction`, нормировка проверяется точно. Выбор символов использует целочисленные накопленные веса и `randrange`, поэтому дроби не округляются до float. Числа с плавающей точкой используются только при выводе и расчёте логарифмов. В отличие от непосредственного `log2(p)`, разность логарифмов числителя и знаменателя не превращает очень малую положительную дробь в ноль перед логарифмированием.

3. Для равномерного кода перечисляются типы (n₁,…,nₖ), а не kⁿ слов. При общем знаменателе D вероятность слова имеет вид ∏wᵢⁿⁱ / Dⁿ; числители, мощности типов и накопленная вероятность считаются целыми числами. Сортировка точная, пограничный тип берётся частично. Для одного n число типов T=binom(n+k−1,k−1); время O(n²+kT+T log T), память O(n²+kT), без учёта стоимости длинной арифметики. Для таблицы суммируем эту оценку по n. Полный перебор оставлен только тестовым эталоном при n≤6. Компактное описание кода хранит границу выбора и порядок нумерации вместо огромной таблицы слов.

4. В zmh используется канонический код Хаффмана. Заголовок: сигнатура 4 байта, исходный размер 8, число полезных битов 8, SHA-256 32, число символов 2 и по 2 байта на символ (значение и длина). Итого 54+2m байта, где m — число различных байтов. Хранение 256 частот потребовало бы больше места; длин достаточно для однозначного восстановления канонического кода. Пустой файл имеет только заголовок; для одного символа длина кода нулевая, число повторов известно из исходного размера.

5. Сигнатура отличает чужой формат, размер файла выявляет обрезанный поток, проверка структуры и SHA-256 выявляет повреждение. Неиспользованные биты последнего байта обязаны быть нулями. Восстановление сначала идёт во временный файл, который сохраняется только после проверки. Контрольная сумма выбрана вместо одной проверки длины: инверсия бита может сохранить длину и дать другой корректно разбираемый поток. Если повреждено само поле размера или сигнатура, причина может выглядеть как обрезание или чужой формат: по одним байтам нельзя всегда восстановить историю повреждения.

Все четыре примера имеют алфавит {0,1,2}, четыре модели и период длины 6.
Модели: m0=(4/5,3/20,1/20), m1=(1/20,4/5,3/20), m2=(3/20,1/20,4/5), m3=(1/3,1/3,1/3).

### Описание сохранённого кода

В JSON записаны алфавит, рациональные вероятности, q и список `codes`. Для каждого n сохраняются длина слова, число кодируемых блоков и `last_type` — последний выбранный тип.

1. Перечисляем типы — векторы количеств символов в порядке `alphabet`.
2. Сортируем по паре (вероятность одного блока, вектор количеств) по убыванию. Вероятности сравниваются точно через целые числители с общим знаменателем Dⁿ.
3. Внутри каждого типа слова идут лексикографически. Все типы до `last_type` включаются полностью, из последнего берутся первые `taken` слов. `last_type=null` означает, что кодируются все слова над алфавитом положительных вероятностей; порядок типов остаётся тем же.
4. Номер выбранного слова, начиная с нуля, записывается в системе счисления q с ведущими нулями до `length`. Это его код. Обратное соответствие получается по тому же порядку.

При R>H ошибка стремится к 0, при R<H — к 1. При R=H ответ зависит от распределения источника и округления длины кода.

## Архиватор

H и средняя длина измеряются в битах на исходный байт; остальные размеры — в байтах. Коэффициент равен исходный размер / размер архива. Для пустого файла H=0 и средняя длина=0 приняты по соглашению, коэффициент равен 0.

| russian.txt | 35600 | 3.815158832 | 3.848314607 | 120 | 17125 | 17245 | 2.064366483 |
| english.txt | 20600 | 4.090546968 | 4.126213592 | 102 | 10625 | 10727 | 1.920387806 |
| image.png | 49363 | 7.994664309 | 7.999169418 | 566 | 49358 | 49924 | 0.988762920 |
| repeated.bin | 10000 | 0.000000000 | 0.000000000 | 56 | 0 | 56 | 178.571428571 |
| empty.bin | 0 | 0.000000000 | 0.000000000 | 54 | 0 | 54 | 0.000000000 |
| source8.bin | 100000 | 0.888391891 | 1.201570000 | 60 | 15020 | 15080 | 6.631299735 |

Русский и английский файлы — короткие учебные тексты, повторённые 200 раз. Изображение — PNG со случайными пикселями (seed=8), созданный стандартной библиотекой. source8.bin содержит 100000 символов iid-источника варианта, записанных байтами 0,1,2: та же модель проходит через все три задачи.

Разрыв между H и средней длиной возникает из-за целых длин кодовых слов. Хаффман оптимален среди побайтовых префиксных кодов, но не использует повторяющиеся фразы. Размер архива равен заголовок+ceil(N·средняя длина/8). Изображение уже сжато и увеличивается из-за заголовка; пустой файл тоже увеличивается. Повторяющийся байт хранится без кодового потока.

## Проверки и журнал исправлений

Все проверки tests.py пройдены; их вывод сохранён в RESULTS.md. Для коротких блоков ошибки сверены с полным перебором, файлы после восстановления сравнены побайтово. Проверены seed, память, периодичность, ошибочные распределения, пустой и односимвольный файлы, неполный байт, повреждение и обрезание архива. Бесконечная генерация прекращается Ctrl+C.

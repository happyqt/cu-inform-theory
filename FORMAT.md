# Формат источника

Исходные поля `models`, `switches`, `source` сохранены. Расширение добавляет конечное состояние. Символы, имена моделей, переключателей и состояний — строки. Вероятности — строки вида `"1/3"` или `"0.25"`, неотрицательные и в каждом распределении точно суммируются в 1. Знак деления `∕` также принимается.

## Грамматика

Обозначим `распределение(имена)` как непустой JSON-объект `имя: строка_вероятности`. Неуказанные имена имеют вероятность 0.

| Поле | Содержимое |
|---|---|
| `models` | непустой объект `имя_модели: распределение(символы)` |
| `switches` | объект `имя_переключателя: переключатель` |
| `source` | непустой список имён переключателей, повторяемый циклически |
| `initial` | необязательное распределение начального состояния |
| `transitions` | вместе с initial: `состояние: {символ: следующее_состояние}` |

Алфавит — объединение символов всех моделей, включая символы с нулевой вероятностью. Обычный переключатель — `распределение(модели)`. Расширенный переключатель имеет вид:

```json
{"by_state": {"a": {"m0": "1"}, "b": {"m1": "1"}}}
```

В `by_state` обязательна строка для каждого состояния из `transitions`. В каждой строке `transitions` обязателен переход по каждому символу алфавита. Все ссылки должны существовать. `initial` может не перечислять состояния с нулевой вероятностью. Поля `initial` и `transitions` задаются только вместе.

## Семантика

Перед первым символом состояние выбирается по `initial`. На такте t, начиная с нуля:

1. Берётся переключатель `source[t mod L]`.
2. Если есть `by_state`, выбирается строка текущего состояния; иначе используется обычное распределение моделей.
3. По распределению выбирается модель, затем символ по её распределению.
4. Выдаётся символ, состояние заменяется по `transitions[состояние][символ]`.

Случайные выборы на тактах независимы условно на текущем состоянии и фазе. Реализация сразу выбирает символ из смеси моделей: p(a)=Σwₘpₘ(a). Это даёт тот же закон наблюдаемого процесса.

Без расширения подразумевается одно состояние с петлями по всем символам. Поэтому старые JSON читаются без конвертации, а символы на разных тактах независимы. Начальное состояние само по себе не выводится.

Точная вероятность блока со сдвигом j вычисляется так: j шагов суммируем по всем символам, затем r шагов оставляем только заданные символы. В конце суммируем веса состояний. Среднее по позициям — сумма этих вероятностей для j=0,…,L−1, делённая на L; это не заменяется вероятностью в стационарном распределении.

## Примеры варианта 8

Полные файлы находятся в `examples/`. Во всех k=3, M=4, L=6. Модели m0=(4/5,3/20,1/20), m1=(1/20,4/5,3/20), m2=(3/20,1/20,4/5), m3=(1/3,1/3,1/3), алфавит {0,1,2}.

- **iid.json:** source шесть раз выбирает m0, состояния нет. Независимые одинаково распределённые символы дают стационарный эргодический источник.
- **periodic.json:** source выбирает m0,m1,m2,m3,m1,m2. Разные распределения на соседних тактах обеспечивают нестационарность.
- **markov.json:** состояния — все тройки из {0,1,2}, initial равномерно по 27 состояниям. По состоянию abc выбирается модель mₐ, после выдачи x состояние становится bcx. Это память глубины 3. Равномерное распределение состояний стационарно: каждый столбец матрицы переходов суммируется в 1. Из любой тройки можно попасть в любую за три шага; есть петля в 000. Поэтому источник стационарен и эргодичен.
- **mixture.json:** состояния a,b выбираются с вероятностями 1/2; переходы по любому символу оставляют состояние прежним. В состоянии a выбирается m0, в b — m1. Каждая компонента стационарна, значит смесь стационарна; частота нуля стремится к 4/5 либо 1/20, а не к общей вероятности 17/40. Источник неэргодичен.

Для произвольного марковского источника глубины d состояниями служат контексты из d символов, переход — сдвиг с добавлением нового символа. Любое распределение следующего символа выражается смесью детерминированных моделей символов; при k=3, M=4 для этого достаточно трёх моделей, четвёртая может не использоваться. Если начальный контекст не имеет стационарного распределения, источник не обязан быть стационарным.
